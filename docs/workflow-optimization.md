# 研发平台流程优化

本轮沿现有本地工作台和批准契约修复审查发现的问题，不改变既有产品源码或数据库。

## 可执行字段规格

`FieldRequirement` 与 `FieldSpec` 增加数值边界和文本 `pattern`。普通整数统一为 -2147483648 至 2147483647；需要完整 int64、精确金额或其他数值类型时，必须另建传输和存储契约，不能依赖 JavaScript Number 隐式转换。

例如 `orders.quantity 必须大于0` 必须映射到 `minimum=1` 或等价的 `exclusive_minimum=0`。只保留验收文字、未配置可执行边界的设计被阻塞。解析器保守处理明确、已绑定字段的条件，数值筛选阈值不视为保存约束；不声称证明任意自然语言的全部语义。

Python 基础产品及业务产品将数值边界用于 API、SQL CHECK、前端表单和独立 HTTP 反例；原生业务适配器保留 SQL CHECK 和 API 拒绝输入。无 business 的原生基础适配器尚不能执行新边界，设计明确拒绝。枚举全部选项必须满足长度域且无首尾空白；普通可编辑 datetime 未修改时沿用原始带时区精度值。

Python `pattern` 使用 Pydantic 默认安全正则引擎（拒绝反向引用和环视）及合法 `example` 驱动 API 和验收正例，并验证可构造的格式反例。正则字段暂不同时开放搜索或筛选，因为单个正例不足以证明查询的字段隔离。原生正则暂不支持，避免把 Python 正则语义无声转换成 Java 或浏览器正则。

## 逐功能分派

创建运行时可选择 `allow_custom_extensions=true`。独立需求分析和来源账本先于 `FeatureDesign`，规划器在 `native / declarative / module / blocked` 中逐功能选择路径。基础契约继续执行原有需求覆盖、业务覆盖和适配器设计检查；源码模块精确对应受控任务、文件、场景和批准范围，复用现有候选与隔离证据链。

完整需求的功能 ID、来源和批准摘要持续校验；覆盖不足、缺少隔离执行环境或真实模块代码时不能交付。现有 `batch-import-v1` 安装入口引用的运行时和页面文件缺失，因此明确阻塞。独立模块证据仍属于已审阅合同范围，不可冒充任意原始网站需求已全部完成。

## 恢复、收尾与使用体验

- Python 基础生成在平台临时目录写完整源码再原子发布；发布后的回执中断仅在目标、批准规格和源码哈希匹配时恢复，不清空半成品以外的用户目录。
- 到期提醒绑定当前规则，互不触发其他截止日期或接收者。
- 竞赛专用验收按明确有效来源绑定；独立邀请码不触发竞赛策略，局部取消截止限制或展示要求不解除整体竞赛验收。
- 后端统一返回动作的 `needs_model`；普通交付批准无需继续保留模型配置。UI 草稿保留在页面会话内存，配置返回后可继续；页面刷新仍会清除这份内存草稿。
- 设置表单等待首次异步配置加载并保留用户编辑。项目历史按项目查询、分页；交付中心同时覆盖扩展范围与交付批准状态。
- 客服完整业务 CI 接入 main、PR 和手动触发，相关业务模板修改会触发验收。
